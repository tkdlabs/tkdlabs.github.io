## Overview

I always wanted to learn those barely used words you find in English books. The challenging part is that they are hardly ever used in every day English so it's almost impossible to acquire that vocabulary through daily immersion.

I noticed the e-readers have somewhat fair dictionary support. So I was wondering if it's possible to create a workflow, where you could convert the vocabulary you come across into flashcards easily.

I currently use Kobo Libra Color reader and went on an exploratory journey to see if it's possible to do it.

All code was generated by Claude Code and is experimental. Use at your own risk.

## Project

Extract from the device:

* Dictionary lookups
* Context in which the lookups occurred

This would be a good source for creating vocabulary flashcards in Anki automatically.

## Workflow

This can be easily done while reading an e-book, with almost no overhead:

* Look up word while reading (and select the "Add to My Words" to opt it in).
* Select the sentence surrounding the word to create a highlight.
* Select the highlight once again to remove it (unless you want to really store it persistently)

If you need to look up the word anyway, the extra cost of highlighting the sentence and removing it is almost negligible.

## Details

Kobo maintains an unencrypted database under `.kobo/KoboReader.sqlite`.

I first tried to take a snapshot of the database tables.

We have the Analytics table, that ended up being unreliable, and the WordLookup table that will get populated once you enable "My Words" beta feature.
That table doesn't hold any context of the word that you looked up. That's a problem, especially with more advanced words. Often times a word has 10+ definitions, and to create an effective flashcard you need to know which one to use - the context of the sentence in which the word appears is a must.
If you create a highlight of a book it will be stored in the Bookmark table with the fragment you highlighted. However, if you remove the highlight, that row will be gone. So we need to find a way to archive this temporary highlight.

Well that's where the power of database triggers comes. Nothing is stopping you from creating a trigger that will be invoked upon adding a row to the table and creating your own copy of that row in your own table. That's the approach I used - triggers to archive the data I'll later be interested in.

After some experimentation, the WordLookup table was reliable and never deleted, and I haven't created a copy of it.
But the highlights table should be stored into PersistentBookmark table that contains highlighted areas, even if they are removed by the users (we only react on insert/update on the Bookmark and ignore deletes).

Example of the key trigger. Note that we add our timestamp at the end:

```sql
-- ============================================================================
-- TRIGGER: Archive Bookmark on INSERT
-- ============================================================================
CREATE TRIGGER IF NOT EXISTS trg_bookmark_insert_archive
AFTER INSERT ON Bookmark
FOR EACH ROW
WHEN NEW.Type = 'highlight' OR NEW.Type = 'annotation'
BEGIN
    INSERT OR IGNORE INTO PersistentBookmark
        (BookmarkID, VolumeID, ContentID, StartContainerPath,
         StartContainerChildIndex, StartOffset, EndContainerPath,
         EndContainerChildIndex, EndOffset, Text, Annotation,
         ExtraAnnotationData, DateCreated, ChapterProgress, Hidden,
         Version, DateModified, Creator, UUID, UserID, SyncTime,
         Published, ContextString, Type, Color, DateArchived)
    VALUES
        (NEW.BookmarkID, NEW.VolumeID, NEW.ContentID, NEW.StartContainerPath,
         NEW.StartContainerChildIndex, NEW.StartOffset, NEW.EndContainerPath,
         NEW.EndContainerChildIndex, NEW.EndOffset, NEW.Text, NEW.Annotation,
         NEW.ExtraAnnotationData, NEW.DateCreated, NEW.ChapterProgress, NEW.Hidden,
         NEW.Version, NEW.DateModified, NEW.Creator, NEW.UUID, NEW.UserID,
         NEW.SyncTime, NEW.Published, NEW.ContextString, NEW.Type, NEW.Color,
         CURRENT_TIMESTAMP);
END;
```

When syncing the device over USB cable:

* Run "kobo\_correlation\_plugin.py" on the database path (by default it's in .kobo/KoboReader.sqlite)

This extracts out all new dictionary lookups, with timestamps and the highlighted context into a CSV file.
You can feed it into your Anki (manually or automated).
I'll cover my Anki automation in the future blog post.

The core of correlation logic:

```python
       # Find highlights in the same volume within the time window from PersistentBookmark
        cursor.execute("""
            SELECT Id, BookmarkID, Text, DateCreated, VolumeID
            FROM PersistentBookmark
            WHERE VolumeID = ?
              AND Type = 'highlight'
              AND DateCreated BETWEEN ? AND ?
              AND Text IS NOT NULL
            ORDER BY abs(julianday(DateCreated) - julianday(?))
        """, (volume_id, start_time, end_time, lookup_time))

        all_candidates = cursor.fetchall()
        matches = []
        all_scored = []
        word_lower = word.lower()
        word_pattern = re.compile(r'\b' + re.escape(word_lower) + r'\w*\b', re.IGNORECASE)

        if self.verbose:
            print(f"  Found {len(all_candidates)} highlights in time window (+/- {time_window_minutes} min)")

        for row in all_candidates:
            highlight_text = row['Text']
            if not highlight_text:
                continue

            # Calculate confidence based on multiple factors
            confidence = 0.0
            score_details = {}

            # Factor 1: Exact word match (case-insensitive)
            word_match = word_pattern.search(highlight_text)
            word_score = 0.5 if word_match else 0.0
            confidence += word_score
            score_details['word_match'] = word_score

            # Factor 2: Time proximity (closer = higher confidence)
            highlight_dt = parse_datetime(row['DateCreated'])
            if highlight_dt:
                time_diff_minutes = abs((highlight_dt - lookup_dt).total_seconds() / 60)
                time_factor = max(0, 1 - (time_diff_minutes / time_window_minutes))
                time_score = time_factor * 0.3
                confidence += time_score
                score_details['time_proximity'] = time_score
                score_details['time_diff_minutes'] = time_diff_minutes
            else:
                score_details['time_proximity'] = 0.0
                score_details['time_diff_minutes'] = None

            # Factor 3: Word appears near the beginning of highlight (more likely context)
            position_score = 0.0
            if word_match:
                position_factor = 1 - (word_match.start() / len(highlight_text))
                position_score = position_factor * 0.2
                confidence += position_score
                score_details['position'] = position_score
                score_details['word_position'] = word_match.start()
            else:
                score_details['position'] = 0.0
                score_details['word_position'] = None

            score_details['total'] = confidence

            if self.verbose:
                all_scored.append((row['Id'], highlight_text, confidence, score_details))

            # Only include in matches if word appears in highlight and confidence is above threshold
            if word_match and confidence > 0.3:
                matches.append((row['Id'], highlight_text, confidence, score_details if self.verbose else None))
```

The script is finding time correlations, because the Kobo device doesn't have a way to link the creating of highlights with the looked up word. So we are finding the highlight that contains the looked up word, plus we prioritize if highlight was created around the time of dictionary lookup.
